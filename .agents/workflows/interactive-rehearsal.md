# Interactive Rehearsal Workflow

适用于试剧情分支、跑角色反应、探索“如果主角这么做”的现场反馈。

互动试演是沙盘，不是正文事实源。它可以帮助发现更好的桥段、冲突、对白和角色主动性，但只有被整理进正文、设定、大纲、章节组细纲或创作进度后才生效。

## Steps

1. 读取目标作品 `README.md`、`ka.yaml`、`agent_surface.state`，确认 `paths.interactive`、`paths.progress`、`paths.chapter_groups`、`paths.canon` 和 `paths.drafts`。
2. 读取本轮相关的角色卡、正式设定、当前章节组细纲、最近正文或接手说明。
3. 明确试演边界：场景、在场人物、主角可行动空间、用户想测试的问题。
4. 生成一回合或数回合试演时，隐式完成：识别用户行动 -> 判断角色和世界规则 -> 裁定后果 -> 推进场景 -> 打开新的选择点 -> 一致性自检。
5. 输出试演记录到 `paths.interactive`，不要直接修改 `paths.drafts`、`paths.plan`、`paths.chapter_groups` 或 `paths.progress`。
6. 如果试演产生可用结论，单独列“可合入项”和“仍需确认项”。合入前必须再走正式编辑、章节组规划或设定维护 workflow。

## Record Format

```markdown
# YYYY-MM-DD：试演主题

## 试演问题

## 必读事实源

## 初始场景

## 试演回合

## 可合入项

## 仍需确认项

## 不进入正史的分支
```

## Rules

- 不把试演记录当作角色卡、设定或正文。
- 不替用户做重大选择；在风险、代价、信息不足或不可逆选择处停下。
- 角色必须有主动反应，不能长期沉默、等待或机械配合主角。
- 世界规则必须稳定，不能为了试演爽点改写已确认设定。
- 同人项目只能记录自己的原创推演和整理，不提交第三方作品原文、截图或批量引用。
