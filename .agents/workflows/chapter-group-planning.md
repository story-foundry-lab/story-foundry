# Chapter Group Planning Workflow

适用于规划“接下来一组章节”、校准短期细纲、从当前正文进度继续拆分章节组。

章节组不是固定章数批次，而是一个短期情节单元。它服务接下来几章的落笔，不替代总纲、分幕大纲或角色卡。

## Steps

1. 读取目标作品 `README.md`、`ka.yaml`、`agent_surface.state`，确认 `paths.progress`、`paths.chapter_groups`、`paths.plan` 和 `paths.drafts`。
2. 读取 `paths.progress` 下的进度文件，确认当前定稿落点、最近章节摘要和下一章承接提示。
3. 读取最近已写正文，至少最近 2 章；如果正文少于 2 章，读取已有全部正文和接手说明。
4. 读取长期大纲：总纲、当前分幕大纲，以及与本组章节相关的单章大纲。
5. 如果 `paths.chapter_groups` 已有上一组或当前组细纲，读取最近 1-2 个文件，只用于对照计划与实际正文偏差。
6. 如果实际正文明显偏离长期大纲，先指出偏差，并给出两个选项：调整长期大纲，或让下一组细纲把剧情拉回主线。用户没有确认时，不硬写新细纲。
7. 只规划接下来一组章节，输出到 `paths.chapter_groups`。不要一次性批量展开很多组。
8. 章节组细纲可以列待确认点；待确认点不进入正文事实。

## Output Format

章节组文件建议使用：

```markdown
# groupXX：短期情节目标

## 章节组目标

## 承接状态
- 当前进度：
- 主角状态：
- 关键角色状态：
- 未解决钩子：

## 覆盖范围
- 建议章节：
- 预计章数：

## 组内冲突曲线
1. 起点：
2. 升级：
3. 转折：
4. 落点：

## 逐章安排
### 第X章：章节标题
- 本章任务：

- 冲突/阻力：

- 结尾钩子：
- 需要避开的设定冲突：

## 伏笔与回收
- 待埋：
- 待回收：

## 待确认点
-
```

## Rules

- 章节组细纲属于短期执行层，不能覆盖角色卡、正式设定或已写正文。
- 已完成章节复盘写入 `paths.progress`，不要塞回长期大纲。
- 角色状态变化写入正式角色卡或资料库索引前，必须回到正文和设定源核验。
- 如果只是试桥段或分支可能性，先用 `interactive-rehearsal.md`，不要把试演结果直接写成细纲事实。
