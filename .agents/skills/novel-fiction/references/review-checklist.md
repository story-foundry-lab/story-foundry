# 审读报告流程

用于用户要求"审读"、"看下有没有问题"、"合理吗"、"动机够吗"、"评价一下"时。用户没有要求直接改时，只输出审读；用户要求直接改时，审读作为内部步骤。

## 审读前定位

先确认审读对象是整章、场景、段落、角色动机、文风，还是设定一致性。按需读取：

- 角色相关：角色卡
- 本章任务：分幕大纲
- 世界规则：聚落/专项设定
- 文风、节奏、对话、氛围、动作场景：文风学习 README + `style-routing.md`
- 完整质量审查：`review-dimensions.md`
- 三重视角审查：`review-perspectives.md`

## 必看六项

1. 硬伤：错别字、事实矛盾、设定冲突、名称不一致、对话归属不清
2. 人物：言行是否符合角色卡，行动是否由欲望、压力、处境推出
3. 叙事：视角是否漂移，节奏是否塌，推进是否有效
4. 语言：措辞是否出戏，比喻是否越界，句式是否重复或生硬
5. 结构：这段、这场、这章是否有任务，是否空转
6. 一致性：是否和角色卡、设定、大纲冲突，是否偷跑后文

完整审读时，同时按 `review-dimensions.md` 扫读者回报、人物动机、场景结构、文风声音、连续性和作者偏好；输出仍只抓最影响阅读和后续创作的问题。

## 输出结构

按严重程度分三级，每级用表格列出：

### A. 硬伤（必修）

| # | 位置 | 问题 | 说明 |
|---|------|------|------|

硬伤包括：错别字、对话归属不清、世界观违反、事实矛盾、名称不一致。

### B. 中度问题（建议修）

| # | 位置 | 问题 | 说明 |
|---|------|------|------|

中度问题包括：节奏走平、角色对话不符角色卡、比喻出戏、信息重复、视角漂移、插叙手法重复。

### C. 细节打磨（锦上添花）

| # | 位置 | 建议 |
|---|------|------|

细节打磨包括：措辞优化、比喻升级、节奏微调。

### D. 结构观察

不用表格，用段落描述：
- 全章节奏分析
- 主角欲望强度评估
- 悬念/钩子有效性
- 读者回报是否明确
- 场景任务是否完成
- 整体亮点（具体到段落）

## 原则

- 每个问题给**具体位置**（引用原文几个字即可定位）
- 关键问题给**改后文本**，不要只说"可以更含蓄"
- 不要客气，不要"建议""或许"，直接说"改成"
- 亮点也要说，但要具体——"这段好"没用，"刺背蜈那段的体感描写节奏卡得好"有用
- 问题很多时只抓最高价值的 1-3 个，不做低价值穷举
