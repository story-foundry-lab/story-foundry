# 初稿写作模式

用于用户明确说“初稿”“推我一把”“先写下去”“关门写作”“别审了先写”时。这个模式服务创作启动，不用于细密审读、设定核查、名称统一或最终润色。

## 核心原则

- 初稿阶段先推进现场，不做长篇批评。
- 用户卡住时，给具体情境推动：谁进门、什么物件丢了、哪条路暴露、哪个选择必须现在做。
- 用清楚的动作和选择先把段落写出来，不追求漂亮句子。
- 只要用户还在写，就优先让他继续写。

## 可以提供什么

- 下一段的 2-3 个推进选项。
- 一个可直接续写的动作开头。
- 一个具体阻力：光源变弱、门外有动静、物件缺失、路线被堵、证据要转手。
- 一个角色此刻能做的小选择。
- 一段不超过当前上下文承载量的试写。

## 禁止做什么

- 不在初稿阶段展开全书结构评审。
- 不把一个卡点扩成完整设定重构。
- 不用“主题、意义、命运、宏大表达”压住现场动作。
- 不绕回用户刚否定过的表达、动作细节或场景方向。
- 不把未核验设定写成正式事实。

## 切换到修改模式

只有用户明确说“写完了，帮我改”“润色”“审读”“优化”“合入正式稿”时，才切回正式审读或编辑流程。

修改时优先：

1. 删弱解释，保留动作。
2. 被动改主动。
3. 抽象判断改成具体物件、距离、声音、体感和选择。
4. 二稿目标是更清楚，不是更花。

## 输出口径

- 用户要方向：给短选项，不写长分析。
- 用户要续写：直接给可接上的段落。
- 用户要被推动：给一个小阻力和一个行动入口。
- 用户要停下来审：再切回 `review-checklist.md` 或 `edit-verification.md`。
