# 重写与修改流程

用于“重写、换视角、扩写、缩写、改对话、调整动作场景、整章改写”等任务。

## 必读上下文

1. 用户指定的目标文件或段落。
2. 目标段前后 3-5 段；整章重写时读取前一章结尾和后一章开头。
3. 与改动相关的角色卡、正式设定和当前章节组细纲。
4. 涉及文风时读取 `references/style-routing.md` 指向的 1-2 个文风文件。

整章或多章重写时，另读 `references/act-rewrite-supervision.md`；只改句子、错字或小段落时不必扩大上下文。

## 执行规则

- 本轮用户要求优先。用户明确要换视角、删桥段、压节奏时，不被旧进度摘要绑住。
- 局部修改保持最小范围；不要借润色重写整章。
- 全量重写时先列验收条件和保留项，再改正文。
- 重大情节、角色动机、空间关系或设定规则变化必须显式标出后续同步风险。
- 不把审稿意见、章节结构说明、未来信息写入正文。

## 写回边界

- 默认只写回用户指定文件。
- 不因重写自动修改长期大纲；如正文与大纲出现明显偏差，提示用户确认是调整大纲还是调整正文。
- 只有最终正文已经改定，且本轮明确要求同步时，才更新 `paths.progress` 或角色卡。
- 角色状态同步只写已发生变化，不把章节规划或复盘塞进角色卡。
- 改动影响称呼体系、世界规则或关键动机时，按 `references/maintenance.md` 判断是否需要跨文件同步。

## 自验

按 `references/edit-verification.md` 回读。重点检查：

- 改动是否满足用户要求。
- 角色声音和 POV 是否一致。
- 前后文时间、位置、物件、伤势和关系是否连续。
- 是否引入旧名、废名、翻译腔或不自然倒装。
- 是否把草稿、试演、灵感片段写成正式事实。
