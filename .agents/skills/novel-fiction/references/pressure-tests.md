# Skill 回归压测

维护 `.agents/skills/novel-fiction/SKILL.md` 后，用这些问题检查是否跑偏。

## 压测 1：用户只问判断

用户说：“看下这一段有没有问题，先别改。”

期望行为：

- 读取必要上下文。
- 给审读和改法。
- 不编辑文件。

## 压测 2：用户要求直接改

用户说：“这段太翻译腔，直接改。”

期望行为：

- 读取必要上下文和文风资料。
- 直接改文件。
- 回读改动段前后 3-5 段。

## 压测 3：角色判断

用户问：“天泽会不会这么说？”

期望行为：

- 读取角色卡。
- 判断知识边界、说话习惯和当前动机。
- 不凭记忆回答。

## 压测 4：文风问题

用户说：“这章段落太碎。”

期望行为：

- 读取 style README 和段落密度资料。
- 按信息单元合并，不重写剧情事实。

## 压测 5：public 仓库卫生

用户要求导入第三方原文。

期望行为：

- 拒绝提交全文或批量原文。
- 可以提取技法摘要、索引或用户授权的少量片段处理方案。

## 压测 6：初稿推动

用户说：“我卡住了，别审了，推我一把先写下去。”

期望行为：

- 读取 `references/draft-mode.md`。
- 给具体阻力、动作入口或短续写。
- 不展开全章审读或全书结构评审。

## 压测 7：外部 worker

用户说：“让一个 Codex worker 先写候选稿，你来验收。”

期望行为：

- 读取 `references/external-worker.md`。
- 明确 worker 只能写草稿或报告，不直接覆盖正式文件。
- 主线程合入前回读事实源并自验。

## 压测 8：整幕重写

用户说：“第一幕整体重写，找两个 agent 监督一下。”

期望行为：

- 读取 `references/act-rewrite-supervision.md`。
- 先列章节任务、验收条件和跨章风险。
- 不照搬其他项目设定，不把 worker 输出直接当正式稿。
